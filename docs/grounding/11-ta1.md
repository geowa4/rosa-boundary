## 1. Scope & boundaries

**In scope (runtime):** the TA HTTP server (`cmd/server`), middleware chain, authentication/authorization, SQLite/Postgres store, in-process worker pool, executor and its two scopes (Kubernetes via Backplane trusted-action sessions; AWS via backplane-cli cloud credentials), the action catalog and the nine registered actions, the two CLIs (`cmd/action-cli` = executor-direct test CLI; `cmd/rta` = HTTP client), and the AWS resources the two TA Terraform roots declare, treated as static preconditions.

**Out of scope:** `terraform apply`/HCP runs, Konflux/Tekton builds (TA PipelineRuns are held with `false &&` — [.tekton/rosa-trusted-actions-push.yaml#L12-L13](https://github.com/geowa4/rosa-boundary/blob/509078b/.tekton/rosa-trusted-actions-push.yaml#L12-L13)), OpenAPI code generation, the Imposter mock and `tests/proxy-backplane` harnesses (cited only to illuminate the contract), Boundary's own runtime.

**Component boundary vs. Boundary.** TA is a separate Go module ([go.mod#L1](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/go.mod#L1)), separate image ([Containerfile#L1-L20](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/Containerfile#L1-L20)), two independent Terraform roots/states ([TA AGENTS.md#L20-L23](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/AGENTS.md#L20-L23)). No Go import, Terraform data source, IAM trust, S3 bucket, or log group is shared with Boundary code (grep of `deploy/**/*.tf` for "trusted" matches only `metrics_read_trusted_principal_arns`).
