# PART A — Keycloak identity provider (runtime)

## A.1 Scope & boundaries

In scope: what the identity provider does at token-issuance time for the Boundary CLI — realm/client/mappers/groups, the claims the rest of the system consumes, token lifetimes, redirect URIs, PKCE and device-flow enablement, the CNPG database as state, and the external-secrets path that feeds DB credentials. The operator/kustomize deployment is treated as a static precondition (described, not traced).

Out of scope: `oc apply`, operator reconciliation, image builds, Trusted Actions auth, OCM credential injection.

**Critical framing facts (verified):**

1. **The repository contains no realm definition.** `deploy/keycloak/` holds only a Namespace, a `Keycloak` CR, a `Route`, a CNPG `Cluster`, an `ExternalSecret`, and ESO store/SA manifests — no `KeycloakRealmImport`, no client, no mappers, no groups ([deploy/keycloak file list verified: base/kustomization.yaml, base/namespace.yaml, components/cnpg/{cluster,external-secret-db,kustomization}.yaml, components/keycloak/{keycloak,kustomization,route}.yaml, overlays/dev/{cluster-secret-store,kustomization,secret-store,service-account}.yaml]). The realm JSON exists only as a *documented example to be created* ([docs/configuration/keycloak-realm-setup.md#L32-L34](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/configuration/keycloak-realm-setup.md#L32-L34), [#L181-L194](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/configuration/keycloak-realm-setup.md#L181-L194)). **DRIFT:** [docs/README.md#L24](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/README.md#L24) and [docs/runbooks/troubleshooting.md#L73-L88](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/runbooks/troubleshooting.md#L73-L88) refer to `keycloakrealmimport boundary-realm` as if it existed in the deployable tree.
2. **The production/staging IdP is Red Hat EmployeeIDP, not the self-hosted Keycloak.** CLI compiled defaults: `keycloak_url=https://auth.redhat.com/auth`, `keycloak_realm=EmployeeIDP`, `oidc_client_id=rosa-boundary-sre` ([internal/config/config.go#L68-L70](https://github.com/geowa4/rosa-boundary/blob/509078b/internal/config/config.go#L68-L70)). Staging Terraform workspaces pin `keycloak_issuer_url = https://auth.redhat.com/auth/realms/EmployeeIDP` ([hcp-terraform/rosa-boundary/main.tf#L250-L251](https://github.com/geowa4/rosa-boundary/blob/509078b/hcp-terraform/rosa-boundary/main.tf#L250-L251), [#L414-L415](https://github.com/geowa4/rosa-boundary/blob/509078b/hcp-terraform/rosa-boundary/main.tf#L414-L415)). EmployeeIDP's realm, client and mapper configuration is **entirely external to this repository**; its emitted claims are inferred only from consumers (Lambda, CLI, IAM) and the debug script [tests/oidc-token-debug.py#L210-L257](https://github.com/geowa4/rosa-boundary/blob/509078b/tests/oidc-token-debug.py#L210-L257).
3. The self-hosted Keycloak in `deploy/keycloak/` is therefore a **dev IdP** whose realm must be created out-of-band (admin console / API / an uncommitted import file).
