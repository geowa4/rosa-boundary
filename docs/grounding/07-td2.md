## B10. Open questions / verification gaps (Part B)

1. **Legacy-fallback doc drift.** [investigations-and-tasks.md#L155](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L155) says "Missing creation time does not bypass the grace period"; code treats a missing `CreatedAt` as immediately stale when idle ([RI#L293-L303](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/handler.py#L293-L303), tests [#L828-L845](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/test_handler.py#L828-L845)). Also the FAQ "Are investigations automatically cleaned up? No." ([#L188-L190](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L188-L190)) contradicts the reaper section ([#L153-L155](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L153-L155)) and the table ([#L57-L59](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L57-L59)) which omits the reaper as a cleaner of APs.
2. **Identifier regex mismatch** between creator and reaper (G19): which is authoritative? Any existing APs with leading `-`/`_` ids would be permanently un-reapable. Settle by `DescribeAccessPoints` in each environment.
3. **Reaper S3 backup completeness and cost**: no incremental upload, re-uploads on every retry (G15); `upload_file` multipart requires `s3:AbortMultipartUpload` for cleanup on failure (not granted; the bucket's 7-day abort lifecycle at [s3.tf#L131-L137](https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/s3.tf#L131-L137) mitigates). Is the 300 s Lambda budget adequate for real workspaces? UNVERIFIED — needs a live run with a multi-GB directory.
4. **Deadline is soft while a session is open** (G12). Is "indefinite extension by keeping a shell open" acceptable, or should the reaper enforce a hard upper bound? Not stated in docs ([investigations-and-tasks.md#L147-L151](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L147-L151) omits the protection).
5. **`close-investigation` family prefix coupling** to `cfg.ClusterName` (B6, G7): confirm all deployments keep `aws_ecs_cluster.main.name == aws_ecs_task_definition.rosa_boundary.family`; consider returning the base family from `get_config`.
6. **Orphan ACTIVE task definitions** (G7, G18) have no reconciliation path. Confirm whether an operator runbook exists.

9. **`StopTask` IAM condition uses `ForAnyValue:StringLike`** on a single-valued tag key ([iam.tf#L328](https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/iam.tf#L328)); the LocalStack policy-simulation test is skipped ([test_task_timeout.py#L262-L267](https://github.com/geowa4/rosa-boundary/blob/509078b/tests/localstack/integration/test_task_timeout.py#L262-L267)). Verify once against real IAM.
