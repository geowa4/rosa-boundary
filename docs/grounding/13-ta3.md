## 10. Open questions / verification gaps for the maintainer

1. **Does the deployed stage image start at all?** Terraform supplies no AWS region allowlist; a server at this commit exits at startup ([main.go#L256-L260](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/cmd/server/main.go#L256-L260)). Settle: check `/ecs/rosa-trusted-actions` for the fatal string, or map the pinned digest to a source revision.
2. **Shared account/VPC with Boundary.** Same `vpc_id` and private subnets are Git-managed; same AWS account is implied by variable-set names only. Settle: compare the role ARN behind `rosa-trusted-actions-rosa-boundary-stage-…-aws-dynamic-creds` with Boundary's `150100906299`.
3. **Is the live TA infra equal to this Terraform copy?** HCP still points at the old repo. Settle: `terraform plan` from the live workspace vs this tree.
4. **Read-side authorization is role-agnostic.** Any configured role (incl. `ROSAAiAgent`) can read every execution's output and the entire audit log. Is that intended? Output can contain Secret `data` when secrets are allowlisted.
5. **Namespace allowlist in stage.** HCP stage sets no `allowed_namespaces` → permissive mode unless set in the UI. Settle: read workspace variables (not via UI edits, per repo policy).
6. **Executor authorization vs. actual access for `describe-nodes`, `list-alerts`, `get-pull-secret-email`**: the authorizer judges caller params, not what the action reads; least privilege depends entirely on Backplane honouring `RequiredRBAC`. Needs a Backplane-side verification that a `CreateTrustedActionRequest` cannot be widened and that `clusterRoleRules` are accepted for `describe-nodes`.
7. **Backplane session lifecycle.** TA never deletes trusted-action instances; what is Backplane's `expiry`, and are two sessions per `list-alerts` acceptable?
8. **Audit correlation gap.** The S3-forwarded per-action audit record has no execution id; the DB audit entry for GETs has no execution id; failure reasons live only in CloudWatch. Decide the authoritative audit source and whether the `audit.Logger` TODO ([main.go#L213-L218](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/cmd/server/main.go#L213-L218)) is on a roadmap.
9. **Unused config/IAM surface.** `ROSA_TA_ALLOWED_ACCOUNTS`, `ROSA_TA_S3_BUCKET/PREFIX`, task-role S3 `PutObject` and `cloudwatch:PutMetricData` are dead. Remove or implement?
10. **Stale `running` rows and unbounded tables.** No reaper, no retention; single SQLite writer on a `chmod 777` host path reachable via SSM. Is Postgres/Aurora (Phase 2 placeholders) still planned, and what is the retention policy for execution outputs containing cluster/AWS data?
11. **Stage transport.** HTTP-only internal ALB and permissive CORS (`*` with credentials) — acceptable for stage? `rta` refuses to send tokens over HTTP, so how are stage callers expected to connect?
12. **Dependency behaviours relied upon but unverifiable here:** ocm-sdk `authentication.Handler` expiry/issuer/audience checks and JWKS caching; `Connection.TokensContext` refresh; backplane-cli assume-role chain, egress-IP restriction, STS session duration and `GetCloudCredentials` region semantics. Pin and review those versions ([go.mod#L24-L27](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/go.mod#L24-L27)).
13. **HCP secret placement.** The Git-managed TA definition attaches `ocm_client_secret`/`backplane_client_secret` as **regional** workspace variables ([main.tf#L207-L224](https://github.com/geowa4/rosa-boundary/blob/509078b/hcp-terraform/rosa-trusted-actions/main.tf#L207-L224)), but only the **global** root declares those variables ([global/variables.tf#L50-L68](https://github.com/geowa4/rosa-boundary/blob/509078b/components/trusted-actions/terraform/global/variables.tf#L50-L68)); the global workspace block declares none of them. Either the live global workspace carries them out-of-band or the definition is wrong — settle in HCP.
14. **OpenAPI vs implementation drift** (catalog/describe `security: []`, 400/429/502 codes, `timed_out`, `audit-disabled`, `execution_id` on GET, `path` incl. query, ManifestWork fields): decide whether the spec is aspirational or should be trimmed to what the server does.
