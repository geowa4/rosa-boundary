# PART B — Audit evidence

## B.1 Scope & boundaries

Every artifact that records what happened in a Boundary task, where it lands, who can produce/read it, what prevents it, and how an auditor proves it exists for a given `(cluster_id, investigation_id, task_id)`. Includes: container stdout/stderr logs, ECS Exec session I/O logs, Lambda logs, Bedrock invocation logs (CloudWatch + S3 large payloads), the S3 audit escrow sync, the investigation reaper's final backup, S3 bucket controls, reader access paths, CloudTrail status, and retention knobs. Terraform resources are described statically. Excludes: Trusted Actions audit, Keycloak logs, laptop-side CLI logs.

## B.4 Data-flow traces

### Trace B-1: Container stdout/stderr → CloudWatch

Entrypoint and child write to the container's stdout/stderr; awslogs driver (execution role) ships to `/ecs/${project}-${stage}` stream `rosa-boundary/rosa-boundary/<task-id>`; retention `log_retention_days` (default 7; staging workspaces set 90) (https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/ecs.tf#L25-L31 ; https://github.com/geowa4/rosa-boundary/blob/509078b/hcp-terraform/rosa-boundary/main.tf#L497-L499). Content: boot lines (OC warning, "Configured oc/kubectl to use proxy", region autodetect, audit-not-configured warning, task timeout notice), exit lines ("Auto-generated S3 audit path: ...", "Syncing /home/sre to ...", "Warning: S3 sync failed or timed out"). **Interactive shell I/O is not in this group** (it goes to SSM session logs). Not KMS-encrypted (no `kms_key_id` on this group). Async; CloudWatch delivery is best-effort on SIGKILL (last lines may be lost).

### Trace B-2: ECS Exec session I/O → CloudWatch (KMS)

Cluster `execute_command_configuration { kms_key_id = exec_session; logging = OVERRIDE; cloud_watch_log_group_name = ssm_sessions; cloud_watch_encryption_enabled = true }` (https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/ecs.tf#L10-L20). No S3 destination for session logs is configured. Group `/ecs/${project}-${stage}/ssm-sessions` has `retention_in_days = var.retention_days` (default 90) and `kms_key_id = exec_session` (https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/ecs.tf#L33-L40). The in-task SSM agent writes with the task role (`ssm-session-logging` policy) and uses the KMS key via `kms-exec-session`. Every `ExecuteCommand` — interactive join, `credentials configure ocm`, `credentials clear ocm` — produces one session and therefore one stream. Terminal transcript includes everything echoed, so credentials pasted by a user (e.g. `oc login --token=`) are recorded; the helper disables echo to keep the OCM token out (A.4 Trace A-3 note).

### Trace B-4: Reaper final backup (reap-investigations Lambda)

Scheduled every `investigation_reaper_schedule_hours` (8); for investigations with no running tasks and age > `investigation_grace_period_hours` (168): uploads EFS directory `/mnt/efs/<cluster>/<investigation>/` to `<bucket>/<cluster>/<investigation>/reaper-final-backup/` with boto3 (regular files only, skips symlinks, deadline = remaining Lambda time − 30 s, min 10 s, Lambda timeout 300 s), **refuses to delete the directory if backup fails or `S3_AUDIT_BUCKET` is unset**, then `shutil.rmtree`, deletes AP and task definitions (https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/handler.py#L522-L660 ; #L698-L707 ; https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/lambda-reap-investigations.tf#L174-L214 ; tests https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/test_handler.py#L1022-L1216). Grep of `backup_investigation_to_s3` for exclusions: check `test_s3_backup_skips_excluded_paths` (https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/test_handler.py#L1071) — the reaper reads EFS, where `.config/ocm`/`.kube` never exist (task-scoped volumes), so credential exclusion is structural rather than pattern-based. `close-investigation` (CLI) performs **no** S3 backup (https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L161-L165).

### Trace B-5: Bedrock invocation logging

See A.4 Trace A-5 steps 4. Account/Region-wide: records every Bedrock Runtime caller in the account, not just Boundary tasks. Text only; image/embedding/video disabled. CloudWatch group retention `retention_days`, KMS `bedrock_invocations`; S3 bucket lifecycle expires objects after `retention_days`, SSE-S3, TLS-only, BucketOwnerEnforced, public access blocked, **no Object Lock** (https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/bedrock-logging.tf#L60-L85 ; https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/bedrock-large-payloads.tf#L8-L51). Records carry the caller IAM identity (task role ARN) and request IDs; they do **not** carry the ECS task ID or SRE identity (AWS record schema; correlation only by timestamp against session logs — UNVERIFIED whether the Bedrock log `identity.arn` includes the assumed-role session name that Fargate uses, which embeds the task ID).

### Trace B-6: Lambda logs

- create-investigation: OIDC validation, group/ABAC decisions, AP reuse/creation, task def registration, run_task, tagging; also a CloudWatch EMF task-creation metric (`emit_task_creation_metric`) (https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/create-investigation/handler.py#L319).
- reap-tasks: per-run counts `checked/stopped/skipped/protected/errors`, task IDs stopped with deadline values, session-check failures (https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-tasks/handler.py#L195-L206).
- reap-investigations: backup byte/file counts, refusals (https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/reap-investigations/handler.py#L637-L660).
All with `log_retention_days` (7 default; 90 staging); not KMS-encrypted.

### Trace B-7: Optional cross-account replication

When `audit_replication_bucket_arn` and `audit_replication_account_id` are set: replication rule `replicate-to-audit-account`, delete-marker replication on, replica modifications on, ownership → Destination; destination must have versioning + Object Lock COMPLIANCE ≥ retention (comment) (https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/s3.tf#L75-L120). Staging workspace does not set these (grep) → disabled.

### Trace B-8: CloudTrail

**No root in this repository configures CloudTrail** (grep of all `.tf` for `cloudtrail` returns nothing). Docs assert "All S3 access is logged via CloudTrail" and list CloudTrail as an audit source; README says "Enable CloudTrail" as a recommendation (https://github.com/geowa4/rosa-boundary/blob/509078b/docs/runbooks/audit-log-access.md#L225 ; https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/overview.md#L100 ; https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/README.md#L660). Whether a management-event trail exists is an account-level assumption outside this repo; **S3 data events** (PutObject into the audit bucket by the task role) are not logged by a default management trail and would need an explicit data-event selector. ## B.10 Open questions / verification gaps (Part B)

1. **stopTimeout (120 s) vs SYNC_TIMEOUT (300 s).** The code comment and overview.md say the timeout "prevents a hung sync from blocking shutdown past the ECS stop timeout"; arithmetically it cannot. Decide: raise `stopTimeout` (Fargate max 120 s — so it cannot be raised; UNVERIFIED current limit), lower `SYNC_TIMEOUT` to <120 so the warning is at least emitted, or add a pre-stop sync trigger (e.g., `stop-task` running an exec `sync` before StopTask). Live test: create a >1 GB home and stop; inspect prefix completeness and container exit reason.
2. **No completion marker.** Nothing distinguishes a complete snapshot from a partial one. Candidate: write a manifest/`.sync-complete` object last (would also give the auditor a positive assertion).
3. **ECS Exec session log stream naming** (`ecs-execute-command-<SESSION_ID>`) comes from README only; `docs/configuration/aws-iam-policies.md#L460-L469` shows a different pattern (`rosa-boundary/<task-id>/<timestamp>`) — doc drift; verify live with `describe-log-streams`.
4. **CloudTrail**: not in repo; docs claim it. Confirm an org/account trail exists and whether S3 **data events** for the audit bucket are enabled; otherwise task-role PutObject calls are unattributable.
5. **Identity correlation gap**: in-container AWS actions (S3 writes, Bedrock calls) are performed by the shared task role; SRE identity exists only in ECS task tags (purged after task stop) and Lambda logs. Confirm create-investigation logs persist `uuid`/`oidc_sub` next to the task ARN at INFO level (grep suggests only warnings mention `username`); otherwise after ~1 h a task ID cannot be mapped to a person without CloudTrail.
6. **Session log captures stdin?** Whether the OCM base64 payload appears in the ECS Exec transcript despite `stty -echo` is untested live. The design depends on it not appearing.
7. **Task role can PutLogEvents into the ssm-sessions group** (any stream under the group). Integrity of session transcripts against an in-container adversary is therefore convention-only; consider restricting or accepting.
8. **Audit reader role** is outside the repo (app-interface). Its exact policy (read `{account}-rosa-boundary-{env}-*` — which also matches the `-bedrock-invocations` bucket) is UNVERIFIED; confirm scope and whether it includes `s3:GetObjectVersion`.
9. **Reaper vs close-investigation**: `close-investigation` deletes the AP without any backup; afterwards the reaper (AP-driven discovery) may never back up or delete that directory. Verify `list_investigation_access_points`-based discovery and decide whether `close-investigation` should trigger a backup.
10. **Untested areas**: no test executes the real `aws s3 sync` against LocalStack (test_s3_audit simulates filtering with boto3); no test of signal timing / `timeout` interaction / SIGKILL; no test that `cleanup` exits 0 on sync failure (only that it calls sync); no Terraform test asserts `stopTimeout`, awslogs options, `execute_command_configuration`, S3 Object Lock/replication/lifecycle (LocalStack tests create their own buckets rather than planning `s3.tf`); kube-proxy LocalStack tests register a hand-built task definition that includes a `secrets` block the Terraform base lacks (https://github.com/geowa4/rosa-boundary/blob/509078b/tests/localstack/integration/test_kube_proxy_sidecar.py#L100-L106 vs https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/ecs.tf#L175-L224), so they do not validate `ecs.tf`. Shell tests run via `make test-shell` (bats) and `scripts/test_all.py` (https://github.com/geowa4/rosa-boundary/blob/509078b/Makefile#L161-L172 ; https://github.com/geowa4/rosa-boundary/blob/509078b/scripts/test_all.py#L175); whether CI runs them is UNVERIFIED (no `.github/workflows` in repo; `.tekton` pipelines not inspected for bats).
