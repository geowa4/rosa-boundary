## A10. Open questions / verification gaps (Part A)

1. **IAM resource type for `DeleteAccessPoint` in the Lambda policy.** The Lambda's EFS policy grants `elasticfilesystem:DeleteAccessPoint` with `Resource = <file-system ARN>` ([iam.tf#L299-L303](https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/iam.tf#L299-L303)); the SRE-shared and reaper policies use `access-point/*` ARNs for the same action ([iam.tf#L228-L233](https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/iam.tf#L228-L233), [lambda-reap-investigations.tf#L60-L69](https://github.com/geowa4/rosa-boundary/blob/509078b/deploy/regional/lambda-reap-investigations.tf#L60-L69)). If EFS evaluates this action against the access-point ARN, every rollback `delete_access_point` in the Lambda ([H#L899](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/create-investigation/handler.py#L899), [#L976](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/create-investigation/handler.py#L976), [#L1032](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/create-investigation/handler.py#L1032), [#L1085](https://github.com/geowa4/rosa-boundary/blob/509078b/lambda/create-investigation/handler.py#L1085)) fails with AccessDenied and orphans the AP. 2. **Docs vs code on duplicate handling.** [investigations-and-tasks.md#L14](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L14), [#L26](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L26), [#L87](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L87), [#L99](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L99), [#L208-L210](https://github.com/geowa4/rosa-boundary/blob/509078b/docs/architecture/investigations-and-tasks.md#L208-L210) say a second launch returns HTTP 409 and the caller should `join-task`.
